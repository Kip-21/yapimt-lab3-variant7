# Вопросы к защите лабораторной работы 3

1. **Определение процедуры.** Именованный участок кода между `имя PROC` и `имя ENDP`. Вызывается командой `CALL`, возвращает управление командой `RET`.

2. **Команда CALL.** Помещает в стек адрес следующей команды и передаёт управление процедуре. Для обычного ближнего вызова в Win32 адрес занимает 4 байта.

3. **Команда RET.** Извлекает из стека адрес возврата в EIP. `RET n` дополнительно удаляет `n` байтов аргументов. В нашей процедуре используется `RET`: при `cdecl` аргументы удаляет вызывающий код C++.

4. **Косвенный вызов.** Адрес процедуры берётся из регистра или памяти, например `CALL EAX` или `CALL DWORD PTR [address]`.

5. **Взаимодействие C++ и ассемблера.** Модули собираются отдельно и объединяются компоновщиком. Должны совпадать имена, типы аргументов и соглашение о вызове. `extern "C"` отключает C++-кодирование имени; для x86 `cdecl` имя `MakePalindrome` в объектном файле имеет вид `_MakePalindrome`. Изменяемые EBP, ESI, EDI сохраняются; EBX не используется. EAX, ECX, EDX разрешено изменять. Перед возвратом DF должен быть сброшен.

6. **Глобальные данные.** В одном модуле объект определяется и экспортируется, в другом объявляется внешним. В C++ для общей C-связи используют `extern "C"`, в ASM — `EXTERN` либо `PUBLIC`. В этой работе данные передаются через аргументы, как требует задание.

7. **Аргументы функции.** При `cdecl` помещаются в стек справа налево, очищает стек вызывающая функция. После `PUSH EBP; MOV EBP, ESP` первый аргумент расположен по `[EBP+8]`, второй — `[EBP+12]`, третий — `[EBP+16]`. В программе это адрес исходной строки, адрес результата и длина.

8. **Возврат результата.** 32-битное целое обычно возвращается в EAX, 64-битное — в EDX:EAX, вещественное значение x86 MSVC — в ST(0). Несколько результатов можно записать по переданным адресам. У нас процедура имеет тип `void`, а строка записывается в буфер `result`.

9. **Вызов C++ из ASM.** Объявить внешнюю функцию, согласовать имя и соглашение о вызове. Для `cdecl` поместить аргументы справа налево, выполнить `CALL`, затем удалить аргументы из стека. Результат забрать из соответствующего регистра или памяти.

10. **Локальные данные.** Можно выделить место на стеке командой `SUB ESP, n`, обращаться по отрицательным смещениям от EBP и освободить место перед возвратом. В MASM также есть директива `LOCAL`. В нашей ASM-процедуре локальные переменные не нужны.

11. **Ассемблерные вставки в C++.** В MSVC для x86 используются блоки `__asm { ... }`; в них доступны имена переменных C++. Для x64 MSVC такие вставки не поддерживает. В работе использован отдельный ASM-модуль.

## Как работает программа

`REP MOVSB` копирует исходную строку в результат. Затем ESI устанавливается на последний символ исходной строки. `STD; LODSB` читает очередной байт и сдвигает ESI назад; `CLD; STOSB` записывает его и сдвигает EDI вперёд. После `n` повторений получается строка длиной `2n`, к ней добавляется нулевой байт.

Для пустой строки `JECXZ` пропускает обратное копирование. Счётчик ECX не уходит из нуля в `FFFFFFFFh`. Максимальный размер результата — `2 * 255 + 1 = 511` байтов с учётом нуля.
