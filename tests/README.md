# Проверка лабораторной работы 3

Перед проверкой соберите программу командой `code\build.bat` из корня репозитория.

```powershell
python tests/run_tests.py
.\tests\check_abi.bat
```

`run_tests.py` запускает готовую программу, подаёт строки в CP866 и сравнивает точный стандартный вывод, сообщения об ошибках и коды завершения с ожидаемыми. Первые 18 случаев соответствуют таблице отчёта: 17 строк и конец ввода без строки. Затем проверяется по одной строке каждой длины от 0 до 255 байтов. Эти строки формируются из букв, цифр, пробелов и знаков препинания с начальным значением генератора 7. Поэтому повторный запуск использует те же данные. Всего 18 + 256 = 274 теста. Для каждого запуска в `results.json` записаны номер, имя случая, данные (кроме EOF), фактический вывод, код завершения и результат сравнения. Краткий вывод скрипта сохранён в `program-tests.txt`.

`check_abi.cpp` вызывает ту же процедуру MASM для каждой длины от 0 до 255 и проверяет:

- строку результата и завершающий нулевой байт;
- неизменность исходной строки;
- один контрольный байт перед результатом и один сразу после ожидаемого завершающего нуля;
- сохранение EBX, ESI, EDI, EBP и восстановление ESP после удаления аргументов;
- сброшенный флаг направления DF.

Для сборки этой проверки используется MSVC x86. Вставка `__asm` находится только в проверочном коде; сама лабораторная программа состоит из отдельного модуля C++ и отдельного модуля MASM. Всего 256 проверок процедуры. Исполняемый файл проверки помещается в `tests/build`.

Например, перед `CALL MakePalindrome` в ESI записывается `55667788h`. После возврата ESI копируется в переменную `esiValue`, которая сравнивается с `0x55667788`. Для EDI используется `12345678h`, для EBX — `11223344h`. Значения EBP и ESP сохраняются до вызова и сравниваются после него. Вызывающая сторона удаляет три аргумента командой `ADD ESP, 12`. Флаг DF читается через `PUSHFD; POP EAX` и проверяется маской `0x400`: ожидается ноль.

Буфер заполняется байтами `0xCC`, а адрес результата указывает на его второй байт. Контрольные байты должны остаться равными `0xCC`. Такая проверка обнаруживает запись непосредственно перед результатом или сразу после его конца; она не заменяет проверку всей памяти процесса. Проверяются только допустимые длины 0–255, которые передаёт основной модуль.

## Сохранённые результаты

- `program-build.log` — сборка основной программы скриптом `code/build.bat` с MSVC x86 и MASM из Visual Studio 2026. Проект в IDE для этой сборки не использовался.
- `results.json` — данные и результаты всех запусков программы.
- `program-tests.txt` — краткий итог запуска Python-скрипта.
- `build.log` — сборка и запуск проверки интерфейса C++/ASM.
- `run-info.json` — время проверки, SHA-256 исполняемого файла и исходников.
- `screenshots/11-russian.png` — снимок нативного окна после выполнения `lab3.exe` со строкой `тест` в консоли CP866, без дорисовки текста.
